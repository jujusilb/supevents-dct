B.2 — Séquence : Inscription à un événement (Parcours Nominal)

Ce flux détaille le processus de réservation et de confirmation via Webhook.



Extrait de code

sequenceDiagram

&#x20;   autonumber

&#x20;   participant U as Étudiant

&#x20;   participant FE as Frontend

&#x20;   participant AG as API Gateway

&#x20;   participant Auth as AuthModule

&#x20;   participant Ticket as TicketModule

&#x20;   participant Pay as PaymentModule

&#x20;   participant S as Stripe

&#x20;   participant DB as PostgreSQL

&#x20;   participant R as RabbitMQ

&#x20;   participant N as NotificationModule



&#x20;   U->>FE: Clique sur "S'inscrire"

&#x20;   FE->>AG: POST /inscriptions

&#x20;   AG->>Auth: Valider Token

&#x20;   Auth-->>AG: OK (User Context)

&#x20;   

&#x20;   AG->>Ticket: Réserver place (EventID)

&#x20;   Ticket->>DB: Vérifier disponibilité (Jauge)

&#x20;   DB-->>Ticket: Places disponibles

&#x20;   

&#x20;   Ticket->>DB: Créer réservation (status: PENDING)

&#x20;   Ticket-->>AG: Réservation créée (ID)



&#x20;   AG->>Pay: Initier Paiement (ReservationID)

&#x20;   Pay->>S: Créer Checkout Session

&#x20;   S-->>Pay: URL de paiement / Client Secret

&#x20;   Pay-->>FE: Redirection Paiement

&#x20;   FE->>U: Affiche interface Stripe



&#x20;   Note over U,S: L'utilisateur saisit ses coordonnées bancaires



&#x20;   S->>Pay: Webhook: payment\_intent.succeeded

&#x20;   

&#x20;   alt Paiement validé

&#x20;       Pay->>Ticket: Confirmer réservation (ID)

&#x20;       Ticket->>DB: Update status: CONFIRMED + QR Code

&#x20;       Ticket-->>R: Événement "TICKET\_ISSUED"

&#x20;       

&#x20;       R-->>N: Consomme "TICKET\_ISSUED"

&#x20;       N-->>U: Envoi email (Billet PDF + QR)

&#x20;       Pay-->>S: 200 OK (Webhook reçu)

&#x20;   else Échec (voir diagramme B.3)

&#x20;   end

B.3 — Séquence : Échec de paiement

Ce diagramme se concentre sur la gestion des erreurs et la libération des ressources (jauge).



Extrait de code

sequenceDiagram

&#x20;   autonumber

&#x20;   participant U as Étudiant

&#x20;   participant Pay as PaymentModule

&#x20;   participant S as Stripe

&#x20;   participant Ticket as TicketModule

&#x20;   participant DB as PostgreSQL

&#x20;   participant R as RabbitMQ

&#x20;   participant N as NotificationModule



&#x20;   Note over Pay,S: Phase de traitement du paiement...



&#x20;   alt Refus Explicite (Réponse immédiate)

&#x20;       S-->>Pay: payment\_intent.payment\_failed

&#x20;       Pay->>Ticket: Annuler réservation (ID)

&#x20;   else Timeout (Absence de réponse)

&#x20;       Note right of Pay: Délai expiré ou Webhook non reçu

&#x20;       Pay->>Ticket: Annuler réservation (ID)

&#x20;   end



&#x20;   Ticket->>DB: Update status: CANCELLED (Libère jauge)

&#x20;   

&#x20;   par Logging \& Notification

&#x20;       Ticket->>Ticket: Log incident (Error 402)

&#x20;       Ticket-->>R: Événement "PAYMENT\_FAILED"

&#x20;       R-->>N: Consomme "PAYMENT\_FAILED"

&#x20;       N-->>U: Envoi email "Échec de paiement"

&#x20;   end



&#x20;   opt Si liste d'attente active

&#x20;       Ticket->>DB: Notifier premier étudiant sur liste d'attente

&#x20;   end
